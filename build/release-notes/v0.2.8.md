## 更新内容

本版修的是「操作了却没反应」那几处：全屏下没法切窗口、改静音或分辨率后第一次重连必定失败、
全屏的自适应缩放与 1:1 切换只在提示里生效（画面不动）。

### 新增：全屏工具栏里的「切换窗口」

全屏时标题栏不可见，原来想切窗口只能先退出全屏。

- 浮层左侧、「桌面分身」之前补了一个按钮，图标与命令和标题栏那个完全一样（向分身发送 `Win+Tab`）。
- 沿用它原有的可用性判断：会话正在注销/关闭时不可点，免得把快捷键发给正在结束的会话。

### 修复：改设置后的自动重连「第一次必定失败」

改静音或改分辨率都会断开重连，日志里几乎每次都先失败一次，手动再点一次就好：

- **分辨率改走和音频同一套带重试的重连**。原来直接连一次，失败就进「连接失败」并弹诊断面板，
  连重试都没有——用户看到的是「切个分辨率就让我修环境」，关掉面板再点启动又一切正常。
- **重试 2 次 → 3 次（2 秒 / 4 秒 / 8 秒）**。断开后立刻重连会被远程桌面服务用「访问被拒绝」顶回来，
  隔几秒再连就能成功；重试次数不够，表现就是「第一次必定失败、第二次才行」。
- **连之前先等分身会话离开 Active**：控件回到「已断开」不代表系统里已经收尾，
  这条判断和「UU 切回分身」那条路径保持一致。

### 修复：切到主桌面后又被连回分身

自动重连是排队等几秒再连的，这期间切走，它醒来照样去连：

- **待重连加代际号**：主动断开、切到主桌面、改尺寸直连，都会作废在途的那一次。
- 服务侧还在等待中的重试同样按代际作废；**待应用的设置不会丢**，留给下次登录收尾。

### 修复：全屏下自适应缩放 / 1:1 切换不生效

提示说「分辨率与窗口不一致，已切换缩放」，画面却没有任何变化；反过来切 1:1 也仍是拉伸的：

- `SmartSizing` 允许联机修改，但控件只在**尺寸变化**时按它重排：改完属性把尺寸推一像素再复位，
  否则属性改了画面不动。
- 全屏**先定缩放模式、再改窗口尺寸**，这一次 resize 就能用上新设置；顺序反过来要等下一次尺寸变化才跟上。
- 尺寸在排队的回调里读，避免排队期间窗口已经变全屏、却用旧尺寸把控件按回全屏前的大小。
