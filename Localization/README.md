# 界面本地化

程序**只内置简体中文**，也没有语言切换入口。换语言的唯一方式是放一个语言文件：

> 与 `DesktopTwin.exe` 同目录、同文件名，扩展名换成 `.lng`
> （`DesktopTwin.exe` → `DesktopTwin.lng`；把 exe 改名，文件名跟着改）。

文件存在就用它，不存在就用内置中文。删掉或改名即切回中文。

本目录随仓库分发已经做好的译文；程序本身不预置任何语言。

| 文件 | 说明 |

没翻到的键回退中文，见下面[「键缺失怎么办」](#键缺失怎么办)。

## 自己做一个语言文件

### 1. 拿模板

```bat
DesktopTwin.exe --export-lng
```

在当前目录生成 `<程序名>.lng`（简体中文原文，带用法注释），**然后直接退出，不打开界面**。
程序清单要求管理员权限，所以这一步会弹一次 UAC。

> 如果目标文件已存在，会先改名成 `<程序名>.bak-<时间戳>.lng` 再写。
> 这是为了防止「只是想看看有哪些键」时把已经译好的文件盖掉。

命令行的提示文字固定英文，也不参与本地化。

### 2. 翻译

只改等号右边的文字，**不要改键名**：

```ini
# 以 # 或 ; 开头的行是注释，空行忽略
Main.Title=Desktop Twin
Menu.LaunchTarget=Launch in the twin now
```

- 编码保存为 **UTF-8**（带不带 BOM 都行；模板自带 BOM，记事本能正确识别）；
- 值里可以用 `\n` 表示换行、`\t` 表示制表符、`\\` 表示反斜杠；
- `{0}`、`{1}` 是占位符，**必须保留**，顺序可以按目标语言的语序调整；
- 同一个键写多次，以最后一次为准；键名不区分大小写。

### 3. 放回去

改名为 `DesktopTwin.lng`，放到 `DesktopTwin.exe` 同目录，重新启动程序即可。

### 4. 确认生效

看日志 `%AppData%\DesktopTwin\logs\desktop-twin-*.log`：

```
已加载界面语言文件 …\DesktopTwin.lng（539 条，共 539 条内置文字）
```

- 条数 = 你文件里有效条数；括号里第二个数是程序内置的总条数；
- 出现「界面语言文件缺少 N 条，缺失的键回退到内置中文」说明还有没翻的；
- 完全没有这行 → 文件名或位置不对。检查：是不是和 exe 同名、是不是同目录。

## 核对没被触发的文案

诊断面板平时只列出**当前存在问题**的检查项。环境正常时，那些结论一行都不显示，
改文案或翻译文时根本看不到。

**按住 Shift 点「控制中心 → 诊断 → 诊断与修复…」**，会多出一个
「未触发（全部检查项）」分区：全部检查项都会列出，未触发的还会附上刚刚读到的实际值
（如 `当前启动类型：Manual`），一眼能分清是文案问题还是环境真的变了。

## 键缺失怎么办

不影响使用，也不需要一次翻完：

- 键没写、值为空、文件损坏 → 该条回退内置中文；
- 键名写错 → 不影响启动，只是那一条不生效；
- 界面上出现英文键名（如 `Menu.LaunchTarget`）→ 说明这个键既没翻译、内置表里也没有，
  属于程序侧的问题，欢迎提 issue。

**程序升级后**：新增的键没有译文，会显示中文；已删除的键留着不报错。
想跟上新版，用 `--export-lng` 重新导出一份，对照补上差异即可。

## 发给上游

欢迎把译文提交回仓库：

1. 放到本目录，命名 `<程序名>-<版本>-<语言>.lng`，例如 `DesktopTwin-0.2.5-JA.lng`
   （语言用 ISO 639-1 两字母码，大写）；
2. 文件开头的注释里写明**译名**、**对应版本**、**条数**，有译者署名也可以；
3. 提 Pull Request 即可。

也可以只自己用——语言文件放在程序目录就能生效。

## 哪些文字不参与本地化

**调试日志与异常堆栈**（`%AppData%\DesktopTwin\logs\desktop-twin-*.log`）始终是中文。

这是刻意的：出问题时支持者需要看的就是它，日志与其显示语言不一致只会增加沟通成本。
命令行导出的提示同理，固定英文且不给译者翻。

## 格式细节（实现）

想了解加载器怎么工作可以看 `src/DesktopTwin/Localization/`：

| 文件 | 职责 |
|---|---|
| `Strings.cs` | 全部内置文字的简体中文原文，**唯一来源**，导出模板也由它生成 |
| `Locale.cs` | 查找、加载、回退、转义；模板生成 |
| `LocExtension.cs` | XAML 标记扩展，界面里写 `{loc:Loc Menu.LaunchTarget}` |
| `LocalizationCommandLine.cs` | `--export-lng` 入口与控制台输出 |
| `README.md` | 本文件 |

几处刻意的取舍：

- **值只裁前导空白**，尾随空格保留——英文的列表分隔符是 `", "`，吃掉了就成了 `","`；
- **文件里的转义只认 `\n` `\t` `\r` `\\`**，不认识的原样保留，避免把 Windows 路径里的
  反斜杠吃掉；
- **加载失败不拦启动**：文件读不了、格式错乱都只是回退中文；
- **控制台输出走 `WriteConsoleW`**，不经过代码页转换。
