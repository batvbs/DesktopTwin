# 排查手册

**先打开诊断面板**：**控制中心 → 诊断 → 诊断与修复…**（启动失败时它也会自动弹出）。
它会把当前环境里可能影响启动的问题列出来，能自动修的右侧直接有「修复」按钮，
不能修的展开就是具体步骤。下面这份手册是面板覆盖不到的部分。

面板之外，再做两件事，能解决一半问题：

1. **控制中心 → 诊断 → 复制环境信息**，把它贴到 Issue 里；
2. 打开 **控制中心 → 诊断 → 打开日志目录**，看最近一次连接失败前的那几行。

程序在连接失败时会自动把「环境预检结论 + RDP ActiveX 的最后一条诊断」拼进提示和日志，
这两处信息通常比错误码本身有用得多。

## 启动之前

### SmartScreen 提示「阻止了无法识别的应用启动」

下载后双击 exe，Windows 会弹：

> Microsoft Defender SmartScreen 阻止了无法识别的应用启动

这是**声誉判定**，不是病毒检出。它由两个条件同时满足才触发：

1. 文件带 **Mark-of-the-Web**——从网上下载的文件会被写入 `Zone.Identifier`
   备用数据流；
2. 该文件**没有 Authenticode 签名**，或者签了名但证书尚未累积下载声誉。

本项目没有代码签名证书，所以**第一个下载它的人必然撞上这个框**，这是预期行为。

> 版本资源里的 `CompanyName`、`FileDescription` 是 exe 内的自由文本字段，
> 用记事本就能改，不构成身份证明。SmartScreen 只认证书链，不认这些字符串。

**判断该不该放行，看哈希而不是看提示**：

```powershell
Get-FileHash ".\DesktopTwin-<版本>.exe" -Algorithm SHA256
# 与 Release 里 README.txt 末尾的校验值逐字符比对
```

一致 → 文件没被动过，可以放行；不一致 → 不要运行，重新下载。

放行的正确做法是**在运行之前解除这个文件的锁定**：

```powershell
Unblock-File ".\DesktopTwin-<版本>.exe"
```

或者右键 exe → 属性 → 勾选底部的「解除锁定」→ 确定。之后每次启动都不再弹。

点「更多信息 → 仍要运行」同样能启动，但它只是给**这一个文件**记一次本地信任，
换台机器或重新下载还会再弹；而且它不校验内容，**不能代替哈希核对**。

### 顺带：UAC 弹窗也显示「未知发布者」

本程序要求管理员权限，提权时 UAC 会显示黄色的「未知发布者」。
那是 UAC 的签名检查，和上面的 SmartScreen 是两套机制，但根因相同——没有代码签名。
两者都只影响「谁发布的」这个判断，不影响程序能否正常运行。

## 连接阶段

### 提示 516 / 「RDP 连接已断开」

这是 RDP 的通用断开码，本身不指向具体原因。按顺序试：

1. 重启本程序再试（首次初始化失败很常见）；
2. 重启系统再试（会话状态可能已经脏了）；
3. 检查注册表 `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server` 的 `fDenyTSConnections`
   是否为 `1`——为 1 时本机 RDP 监听器根本不启动；
4. 确认没有安装 **RDP Wrapper**（它会替换 `TermService` 的 `ServiceDll`，与子会话不兼容）；
5. 确认系统不是经过「优化/精简」的第三方镜像。

### 一直停在「正在连接桌面分身」

- 看日志里有没有 `RDP 登录失败：...`。`0` 表示凭据无效，`-1` 表示访问被拒绝，
  `0xC000006D` 表示用户名或身份验证信息无效。
- 用户名请用 `C:\Users` 下属于你的那个文件夹名，不要填显示名或邮箱（除非确实是 Microsoft 账户登录）。

### 家庭版能用吗

微软文档说不支持，但实测多数家庭版可以建立子会话。程序会提示但不阻止你尝试。
如果反复失败，优先怀疑版本限制。

## 登录阶段

### 密码怎么输都不对

按这个顺序处理，每步之后重试：

1. **关闭 Windows Hello 限制**
   「设置 → 账户 → 登录选项 → 为了提高安全性，仅允许对此设备上的 Microsoft 帐户使用 Windows Hello 登录」→ 关闭。
   这个开关打开时，Microsoft 账户在本机**没有可用的密码凭据**，输什么都会失败。
2. **刷新本地凭据缓存**
   ```
   runas /u:MicrosoftAccount\<你的微软账户> winver
   ```
   例如 `runas /u:MicrosoftAccount\123456@qq.com winver`，输入一次密码，然后回到分身窗口再试。
   适用场景：微软账户在云端改过密码，本机缓存没更新。
3. **改用本地账户**
   在「设置 → 账户 → 你的信息」里改为本地账户登录，或者新建一个本地账户专门给分身用。
   有相当一部分用户只有本地账户才能登录成功。
4. 改完配置后**重启系统**再试。

### 每次启动都要输密码

用 PIN 登录 Windows 时，系统每次都会向分身会话索要密码，这是 Windows 的行为。

想让系统自动登录：<kbd>Win</kbd>+<kbd>R</kbd> → `netplwiz` → 取消勾选「要使用本计算机，用户必须输入用户名和密码」
→ 应用 → 输入 **Microsoft 账户密码（不是 PIN）** → 重启。

## 使用阶段

### 提示「不支持该请求」

目标程序要求提权，而**分身会话内的 UAC 是否可用取决于环境**：

- 有的机器在分身里点「以管理员身份运行」能正常弹出 UAC；
- 有的机器会直接失败。

失败时用 **控制中心 → 选择要在分身中运行的程序…**，勾选「以管理员权限启动目标程序」，
由本程序从外部把进程送进分身。这是唯一稳定可用的路径。

### 鼠标在游戏里不能转视角

RDP 协议不传递鼠标的**相对位移**。这是协议层限制，不是设置问题。
本项目目前不提供相对鼠标转发（见 [ROADMAP](../ROADMAP.md)）。

### 两个桌面里同一软件打架

Chrome、部分游戏启动器等只允许单实例的程序，在两个桌面同时运行会互相抢占，
典型表现是其中一个一直「等待中」。这类程序只能在一个桌面里开。

### 分身里多出一份开机启动项

分身会话登录时会重新执行用户的自启动项。如果某个自启动软件在两个桌面里冲突，
在分身里把它退出，或从启动项里移除。

### 关机 / 重启失败

**正常情况下分身不会挡住关机。** 分身是一个已登录的会话，电源菜单会提示
「其他用户已登录」或「还有其他用户正在使用此电脑」，但这只是告知——点关机/重启照常执行，
系统会把分身会话一起结束（分身里未保存的内容会丢）。

需要多一步确认、或者确实关不掉，通常是下面三种情况，都和「会话存在」本身无关：

1. **分身里的程序不肯结束**：未保存的文档、装到一半的安装程序会拒绝响应
   `WM_QUERYENDSESSION`。关机界面会列出「这些应用阻止关机」并给出**「仍要关机」**按钮，
   点它就能继续关机——不会卡住，也不需要切回分身去点那个看不见的确认框。
   代价只是该程序未保存的内容会丢；想让它正常保存，再切回分身处理。
2. **非管理员或程序化发起关机**：这种调用可能返回
   `ERROR_SHUTDOWN_USERS_LOGGED_ON (0x4A7)`，多见于 Windows Server 与共享工作站。
   用管理员命令行 `shutdown /s /t 0`（程序自己卡住时加 `/f`）即可。
3. **Windows 更新 / 驱动安装占用**：等它跑完，强行断电有风险。

如果只是想清掉会话残留（不影响关机，但占资源、下次启动会重连到旧会话）：
打开 **任务管理器 → 用户**，右键同名用户 → **注销**。

### 远程控制软件连到了分身

UU 远程等不支持多用户的工具可能连到分身桌面。先关闭分身再远控，或改用支持多会话的方案。
反过来也可以用「UU 视角切换」主动在两个桌面之间切换，见下一节。

## 自动登录与视角切换

### 自动登录没生效，凭据框还是弹出来

程序按三条路径依次尝试，前一条不行才走后面：

1. **把凭据直接交给 RDP 客户端**（`ClearTextPassword`），正常情况下根本不弹框；
2. **用 UI Automation 填写「Windows 安全中心」凭据框**，用户名和密码都会填，最多两次；
3. 两次之后**交回手动输入**，不再继续尝试。

第 3 条是有意为之：凭据框反复出现通常说明密码本身不对，继续自动填只会把账户
往锁定策略上推。所以如果它停下来了，先检查密码。

常见原因：

- **填的是 PIN 而不是密码**。Windows Hello 的 PIN 只在本机登录界面有效，
  远程/凭据框要的是账户密码。
- **账户没有密码**。空密码账户默认无法用于 RDP，见下一节。
- **改过 Windows 密码**。已保存的是旧密码，需要重新「设置登录密码…」。
  换过 Windows 账户或换机器后，DPAPI 也解不开旧密文，同样要重设。
- **组织策略禁止保存凭据**（`DisableDomainCreds` 等）。这种情况只能手动输入。

### 本地账户没有密码

**默认不能用于远程桌面。** 这不是本程序的限制，是 Windows 的行为：
RDP 走的是网络登录，而系统默认禁止空密码账户做网络登录
（安全选项「账户: 限制本地账户使用空密码只允许进行控制台登录」，
注册表 `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\LimitBlankPasswordUse = 1`）。
表现就是密码栏留空怎么点都进不去，或者提示凭据无效。

> 微软账户不受影响——它一定有密码，不存在「无密码」这种状态。
> 这一节只针对**本地账户**。

**解决办法：给账户设个密码。**

`Win+R` 输入 `netplwiz`，选中账户 → 「重置密码」，设一个密码后重试。
后续可以把系统自动登录打开，就不用每次输了（见下一节）。

> **不建议用无密码账户。** 空密码意味着本机任何能碰到键盘的人都能直接进你的桌面，
> 而远程桌面本来是要靠密码把这道门关上的。设密码是唯一被推荐的做法。

<details>
<summary>确实无法设密码时（不推荐）</summary>

系统里确实有个开关能放开这个限制：
`Win+R` 输入 `secpol.msc` → 安全设置 → 本地策略 → 安全选项 →
「账户: 限制本地账户使用空密码只允许进行控制台登录」→ 双击 → 选「已禁用」。

家庭版没有 `secpol.msc`，改注册表：
`HKLM\SYSTEM\CurrentControlSet\Control\Lsa` 下的 `LimitBlankPasswordUse` 改成 `0`。

**这不是推荐做法**，列出来只是让卡住的人知道发生了什么。它等于允许任何能连到这台机器的人
用空密码登录你的账户——把远程桌面这道门整个拆掉了。除非这台机器完全不联网、
也没有第二个人能接触到，否则请回到上面去设密码。

</details>

### 想让 Windows 自己记住，不用每次输

用系统级自动登录，效果是开机即进桌面：

1. `Win+R` 输入 `netplwiz`（或 `control userpasswords2`）；
2. 取消勾选「要使用本计算机，用户必须输入用户名和密码」；
3. 点「应用」，保持默认用户名不变，只输入**账户密码**（不是 PIN）；
4. 重启电脑生效。

程序里也有入口：**控制中心 → 自动登录分身 → 打开系统自动登录设置…**，
旁边还有一段并排对比，说明它和「本程序自动登录」的区别。

> 这条路降低的是**整机**安全性：任何能接触到这台电脑的人开机就能进你的桌面，
> Windows 也会把该密码以可还原的形式保存在本机。只在你自己独占的机器上使用。

### UU 视角切换没反应

先分清是「热键没收到」还是「切换逻辑失败」：

- **菜单 → 控制中心 → 快捷键 → 立即切换一次**。这一步不经过热键。
  如果它能正常切换，说明热键那条路有问题；如果它也不行，往下看最后两条。

热键本身按这几条排查：

- **确认开关是勾选的**。菜单标题会显示当前状态和组合键，
  形如「UU 视角切换（已启用 · Ctrl + Alt + U）」。没勾选时按键当然不会有反应。
- **焦点在分身画面内也能触发**（0.2.3 起）。如果 0.2.3 之前遇到「主窗口按有用、
  点进分身画面就没反应」，升级即可——那是 RDP 的键盘钩子把组合键转发进了远程会话。
- **组合键被占用**会提示「已被其他程序占用」，换一个即可（菜单里可录制）。
- **看日志**：`%AppData%\DesktopTwin\logs\` 里搜「全局热键已注册」，
  会写明系统热键是否成功、Raw Input 兜底是否启用。
  两条都失败时才是真的注册不上。

切换逻辑本身的前置条件：

- 需要 **UU 远程正在运行**。切换靠结束它的串流端 `GameViewerServer.exe` 来逼服务重新挑会话，
  UU 没开时按了不会有任何变化。
- 切换完成后**需要在手机上重新连一下 UU**，才会进到新的桌面。
- 切到「整台电脑」时**分身只是断开、不注销**，里面的程序都还在；
  切回来自动重连，不需要重新开游戏。
- 分身尚未启动时按切换，程序会先把它启动起来，这一步可能等十几秒。

## 收集信息

```powershell
# 环境快照（等同界面里的「复制环境信息」）
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' |
    Select-Object ProductName, DisplayVersion, CurrentBuild, EditionID

# 分身会话是否存在
query session

# RDP 主机开关
Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections
```

日志位置：`%AppData%\DesktopTwin\logs\desktop-twin-YYYYMMDD.log`（保留 14 天）。
